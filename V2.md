# Product Hunter V2

Публичный адрес: https://product-hunter.shvarev-demo.ru/ · API: `/api/docs` · состояние: `/api/health`.

## Режимы и источники

Пять этапов: запрос → рынки → перспективные варианты → поставщики → экономика и рекомендации. `analysis_mode=category` ищет различимые варианты категории; `product` проверяет явные характеристики запроса, сохраняет исходный товар даже без подтверждений и описывает отличия аналогов. Дополнительные возможности, которых пользователь не требовал, не превращают совпадение в альтернативу.

| Площадка | Регион покупателей | Валюта |
|---|---|---|
| Ozon, Wildberries | Россия | RUB |
| Amazon, eBay, Walmart | США | USD |
| AliExpress | США | USD |
| Lazada | Сингапур | SGD |

Единый реестр: `backend/marketplaces.py`. Каталог содержит ещё 28 отключённых площадок, недоступных и через прямой API. Поставщики: Alibaba и Made-in-China; до пяти идентифицированных компаний на кандидата. Меньше трёх компаний — допустимый результат с объяснением пробела. Пустой поиск не заменяется демонстрационными карточками.

Публичный поиск показывает выборку, а не полную статистику площадки. Программа не подтверждает продажи, спрос, надёжность компании или доступность торговли для конкретного продавца. Цена без сопоставимой валюты, единицы и комплектации не участвует в автоматическом расчёте.

## API

- `GET /api/marketplaces` — каталог, доступность, страна, валюта.
- `POST /api/research` — `{ "query": "автомобильный чайник 12V", "analysis_mode": "product", "selected_markets": ["ozon", "amazon"] }`.
- `GET /api/research` — история; `GET /api/research/{id}` — состояние, качество, ошибки, расходы.
- `GET /api/research/{id}/live-opportunities` — предварительные и итоговые кандидаты.
- `GET /api/research/{id}/live-evidence`, `/supplier-evidence`, `/economics` — карточки, предложения и сценарии.
- `POST /api/research/{id}/cancel` — отмена. Старый `/skip` выполняет ту же отмену.
- `POST /api/research/{id}/economics/recalculate` — `{ "archetype_id": 123, "market": "ozon", "inputs": { "retail_price": 2500, "supplier_price_usd": 5 } }`. Передаются только изменения; платных вызовов нет.

Адреса `?run=<uuid>` и чтение V1 сохранены. `research_mode=preset|generic` — внутреннее поле совместимости. Старые отчёты не пересчитываются автоматически.

## Группировка и качество

Онтология описывает гипотезы; подтверждённые группы строятся по реальным карточкам порциями по 30. Все ID проверяются относительно текущей порции. Отсутствующие назначения отклоняются, уверенность ниже 0.65 не даёт подтверждённого участника. Допускаются ноль или одна группа. Сбой модели включает консервативную проверку признаков с предупреждением.

Кеш онтологии зависит от запроса, режима, площадок и версии; не переносит `observed_clusters` и ID. Кеш поиска действует шесть часов, сохраняет первоначальные даты и не продлевается копированием кеша. Ответы модели кешируются **внутри исследования** по модели, схеме, инструкциям и полному входу. Повтор успешного оплаченного шага не вызывает модель снова.

`quality`: `pending`, `complete`, `partial`, `insufficient_data`. `status`: `running`, `completed`, `cancelled`, `failed`. Ошибки и пустые результаты поиска не считаются отсутствием конкуренции. Индекс перспективности отделён от покрытия источников. Russia Gap доступен только при наличии российских и зарубежных выборок. Версии формул: `signals_v2`, `final_rank_v2`, `economics_v2`.

## Экономика

Каждая пара кандидат × выбранная площадка получает отдельный сценарий. Расходы и FX по умолчанию — **модельные допущения, не текущие тарифы**. Цена, партия, курс, доставка, импорт, комиссия, исполнение, хранение, реклама, возвраты, налоги, запуск, объёмы и темп продаж редактируются. Происхождение параметра: источник, пользователь, допущение, нет данных.

- Себестоимость с доставкой = закупка USD × курс × (1 + импорт %) + доставка единицы.
- Вклад на единицу = цена − себестоимость − исполнение − хранение − процентные расходы.
- Предельное привлечение = вклад до рекламы, минимум ноль.
- Безубыточность = округлённые вверх расходы запуска / положительный вклад.
- 30/100/300 единиц — изменяемые сценарные объёмы, не прогноз заказов.
- Средства на партию = себестоимость × партия; средства с запуском требуют заданных расходов запуска.
- Окупаемость использует поступления после расходов продажи, размер партии и заданный темп. Если партия не возвращает вложения или данных нет, показатель не рассчитывается.

Ручная цена не повышает достоверность рыночных данных. `TEST` требует достаточных источников цен и покрытия. Решение относится к лучшему рассчитанному сценарию; остальные площадки доступны для сравнения. Тарифы, налоги и импортные ограничения требуют проверки для конкретного продавца.

## Бюджет и экономная разработка

Секреты: `/etc/product-hunter.env`. Тестовый env: `/etc/product-hunter-v2-test.env`. Не копировать ключи в Git, отчёты или чат. DeepSeek не требуется. Поиск использует небольшую Qwen (`PRODUCT_HUNTER_SCOUT_MODEL`), а структурированный разбор — отдельную `PRODUCT_HUNTER_STRUCTURED_MODEL`, по умолчанию `openai/gpt-4.1-mini` через тот же OpenRouter. Разделение устраняет повторные расходы при нестабильном соблюдении сложной схемы дешёвой поисковой моделью. Кеш включает имя модели.

`budget_calls` объединяет поиск, онтологию, группировку и проверку поставщиков. Перед запросом расход резервируется атомарно, затем заменяется стоимостью из ответа API. Оплаченный некорректный JSON тоже учитывается. Неизвестная стоимость сохраняет резерв и показывается отдельно через `cost_breakdown`: это оценка, не подтверждённое списание. Лимит исследования $1.50; существующий дневной лимит сохраняется. Фактическая стоимость может превысить резерв; это внутренний ограничитель следующих запросов, не банковский лимит аккаунта.

| Переменная | Значение | Назначение |
|---|---|---|
| `PRODUCT_HUNTER_EXTERNAL_CALLS` | `all` (по умолчанию) | Поиск и модель разрешены в пределах лимитов |
| та же переменная | `model_only` | В разработке: повторное использование поиска; только дешёвые вызовы модели |
| та же переменная | `off` | Все новые платные вызовы запрещены |
| `PRODUCT_HUNTER_DEVELOPMENT_TOTAL_BUDGET_USD` | `0.72` на текущем тестовом контуре | Общий накопительный предел тестовой БД с резервами, не сбрасывается ежедневно |

В env должна быть одна строка для каждой переменной. Ограничения разработки не переносятся в production. Регрессионные тесты подменяют внешние вызовы и не расходуют баланс. Для тестового поиска разрешаются только отдельные явно ограниченные проверки; кешированные ответы сохраняют первоначальное происхождение и дату.

## Проверки и эксплуатация

Зависимости: `backend/requirements.txt`. Миграции добавочные, по порядку в `backend/migrations`; перед изменениями нужен `pg_dump -Fc`. Для выпуска проверяются 008/009 и применяются 010–012.

```sh
cd /var/www/product-hunter-v2-test
export PRODUCT_HUNTER_ENV_FILE=/etc/product-hunter-v2-test.env
pm2 stop product-hunter-v2-test-worker
/var/www/product-hunter/.venv/bin/python -m unittest discover -s tests -v
pm2 restart product-hunter-v2-test-worker
```

Остановка тестового воркера обязательна: он не должен забирать задания тестов. Набор проверяет отмену во время этапа, повторные задания, бюджет, выбор рынков, валюты, комплекты, нулевые цены, все 91 ID в нескольких порциях, изоляцию кеша, характеристики исходного товара и бесплатный пересчёт. Живая приёмка учитывается отдельно.

Один worker на БД удерживает session advisory lock `7348202`. Только владелец восстанавливает оборванные задания. Повтор не меняет завершённую задачу и не создаёт следующую заново. Перед завершением этапа проверяется отмена под блокировкой строки. Heartbeat доступен через `/api/health`. Интерфейс восстанавливает опрос после обрыва и игнорирует ответы закрытого исследования.

Production: `/var/www/product-hunter`, БД `product_hunter`, API `127.0.0.1:3005`, PM2 `demo-product-hunter-api`, `demo-product-hunter-worker`. Staging: `/var/www/product-hunter-v2-test`, БД `product_hunter_v2_test`, API `127.0.0.1:3015`; просмотр через SSH-туннель.

Выпуск: дождаться отсутствия активных production-задач, сохранить код и дамп в `/var/backups/product-hunter`, применить добавочные миграции, скопировать проверенный код и перезапустить только процессы Product Hunter. `scripts/deploy-v2.py` также переносит учёт расходов тестового аккаунта в дневной бюджет production. `scripts/rollback-v2.sh <архив>` возвращает код, сохраняя добавленные данные БД. Перед откатом нужно завершить активные исследования.
